## 1. 任务要求(验收标准)

**来源:`任务.xlsx` + `AI/课题分析报告.md`**

构建面向中文智能终端(AI 眼镜、车载座舱)的**开集声纹验证模型**,在复杂声学条件下保持稳定识别。

**硬性指标(单说话人噪声,0dB 与 -5dB 两档):**
- 挑战目标:EER ≤ 0.5%(未冲击,差距数量级太大)
- **达标目标(实际主线):EER 相对主验收基线降幅 ≥ 30%**;(基线EER−改进EER)÷基线EER×100%
- clean 退化 < 1pp;阈值验证集确定后测试集冻结
- 其他场景(混响/重叠/跨设备/短语音)不设统一阈值,分项报告 EER、minDCF、ROC/DET、固定阈值 FAR/FRR

**测试场景必须覆盖:** 干净 / 单说话人噪声(SNR=-5、0dB)/ 回声混响(记 RIR、T60)/ 2-3 人重叠(记 TIR)/ 跨设备 / 短语音(1s、3s、5s)。

**数据规定:** 3D-Speaker 中文数据为主验收集(训练集 190GB、579,003 条;测试集 240 人、18,782 条),VoxCeleb 仅限预训练;说话人互不重叠,禁止泄漏。

## 3. 主线故事:五步走到验收线

### 第一步:全量基线 + 环境基建(7.20–7.31,`AI/8.9` 前后)
RTX 3090 云服务器搭环境 → 190GB 数据就绪 → 三模型官方协议校准。横向发现:cross-dialect 最难(12-15%);ERes2Net 全面领先 ECAPA 约 20-26%;B6 仅 12.3M 在 cross-distance 反超 ERes2Net。

### 第二步:首版微调失败(8.3–8.7)
ERes2Net 冻结式微调(冻结 conv1~layer3、分层 LR、clean 占比 15%):**8 条件中 6 个变差**(0dB 8.39→9.71)。归因三层:冻结过保守、clean 占比过低致灾难性遗忘、上层 LR 过高。教训:全参数微调 + 提高 clean 占比 + 降 LR。

### 第三步:纯降噪路线判死(8.10–8.14,`AI/8.17`)
FullSubNet+ 通用降噪前端:0dB 下 denoised 10.11 **比带噪 8.39 还差 1.72pp**。分离度分析定位根因:**降噪抹平了跨句稳定的说话人身份特征**(target 分数 0.422→0.391)。结论:语音增强做声纹前端,不能以 SNR/PESQ 为目标,必须保身份。这条"负增益"发现是后面一切设计的出发点。

### 第四步:注册条件化 TSE 发明与四轮加码(8.24–8.27,`AI/8.26/8.27`)
单说话人噪声本质是"干扰语音",通用增强分不清目标和干扰 → **用注册语音的声纹嵌入做条件,只提取注册说话人**(VoiceFilter 式 FiLM 条件化,详见第 6 节原理)。四轮迭代(proxy 验证集选点,官方只冻结跑一次):

> **口径说明:** 这一阶段(8.24-8.27)的官方链评测统一在 **soup5 冻结验证器后端**上进行(链内 raw 锚点 7.614/9.715,见第 5 节消融表);交付终评换回预训练后端(锚点 8.39/11.06)。两代前端都做过跨后端迁移验证(见 4.2 节矩阵),增益不依赖特定后端。

| 轮次 | 加码 | 0dB / -5dB(soup5 后端官方链) |
|---|---|---|
| Phase 0 | TSE 入融合(零训练) | 7.38 / 9.32 |
| Phase 1 | +说话人保持损失 Lspk(λ=0.3) | 7.29 / 9.20 |
| Phase 2 | +非目标抑制 Lns(τ=0.30, TOPK=8) | 6.52 / 8.17 |
| ext 难例续训三轮 | hard-case 续训 | 5.77 / 6.97 → 5.47/6.46 → **5.24 / 6.10**;ext4 回归 6.16/7.60 → 停 |

### 第五步:时长增强 + 终评交付(8.28–8.30)
1s 短语音降幅偏低(-19%/-22%),改段级随机 {1,2,3}s 时长增强续训 → **交付 checkpoint r5**。统一终评大表:交付 ckpt × {1,3,5}s × 三后端 × 两档噪声,官方管线三卡并行一天跑完(`AI/8.28/final_eval_r5/`);噪声域分表(music/soundbible/speech)、ROC/DET、失败样本挖掘(`AI/8.30`)、clean 基线实测 5.29 一并收口。

## 5. claim vs oracle:两种口径(最重要的诚实章节)

**背景:** 终评按"测试句真实说话人"做条件化(oracle)——部署时做不到,真实系统只知道"声称身份"。周报 8.24-8.28 周主动承诺了 claim-conditioned 重测。8.31 起执行(`AI/8.31/claim_retest/`、`claim_fix/`)。

**三口径定义(`analyze_claim_v2.py`):**
- **raw** = 注册嵌入 vs 带噪原始嵌入(未增强锚点,臂间共用)
- **oracleFE** = 按**真实说话人**条件化增强后打分(= 交付口径,即第 4 节数字)
- **claimFE** = **target 侧同 oracle;冒认(nontarget)侧按声称者条件化增强**(部署真实口径)
- 抽样:全部 211,400 target + 30,000 nontarget(seed 2026),bootstrap 200 次 CI95;自检确认与官方 score 逐位对齐。

**核心结果(r5 交付模型,3s):**

| 条件 | raw | oracleFE | claimFE |
|---|---|---|---|
| 0dB | 8.37 | **4.88**(-41.7% ✅) | **10.72(比 raw 还差 +2.36pp ❌)** |
| -5dB | 11.09 | **5.53**(-50.1% ✅) | **12.85(比 raw 差 +1.76pp ❌)** |

**机理(为什么 claim 崩):** 冒认侧把冒认者语音按声称者条件化增强,前端把"任何人的声音都往声称者拉"→ 冒认分数中位数暴涨(raw 0.044 → claim 0.129,约 3 倍)→ 误接受率上升。**前端把注册身份信息"泄漏"进了增强语音本身。**

**补救扫描(8.31–9.3,12 个臂,`claim_fix/official_*/summary.txt` 全量实测):**

| 臂(训练侧改法) | oracleFE 0dB/-5dB | claimFE 0dB/-5dB | 定性 |
|---|---|---|---|
| r5(交付) | 4.88 / 5.53 | 10.72 / 12.85 | oracle 最强档,claim 最差档 |
| asym30(非目标抑制加量30%) | 5.41 / 6.20 | 9.12 / 10.98 | 沿 trade-off 线回撤 |
| asym50 / 50ap | 6.05 / 7.14 | 8.39 / 10.25 | |
| **asym70** | 6.69 / 8.30 | **8.11 / 10.05** | **claim 首次优于 raw(-3.1%/-9.3%),oracle 退化** |
| ce00e2 / ce05e1 | 7.83 / 9.98 | 7.84 / 10.00 | 前端中性化(≈raw,无害无益) |
| v8c_ce00 | 7.78 / 9.98 | 7.79 / 10.00 | 同上 |
| mix40i30 / mix40i50(训练混入冒认条件) | 4.87 / 5.58 | 10.56 / 12.35 | 与 r5 同病 |
| v8b | 4.79 / 5.48 | 11.42 / 13.49 | 同病加重 |
| **v8d_sil**(+rank/silence 掩蔽,9.2) | **4.73 / 5.39(oracle 全场最优)** | **12.60 / 14.64(claim 全场最差)** | 极端化证实 trade-off |
| 能量门控(energy_gate) | — | 各门限均救不回 | 修不动 |
| raw+claim 融合(fusion) | — | 最优 8.23/10.50 | 仅回到 raw 附近 |

**结论(截至 9.3):**
1. **oracle 口径:两个主后端 -41.7%~-50.4%,大幅超过 -30% 验收线**——这是已交付的成果。
2. **claim 口径:12 臂扫描画出了一条清晰的 oracle-claim trade-off 前沿,没有任何臂能同时过线**;最优 claim 臂(asym70)也只拿到 -3.1%/-9.3%。v6/v8 系列(混入冒认条件训练、silence 掩蔽、rank 损失)全部失败,最激进的 v8d_sil 把 trade-off 推到极端反而证明问题结构性存在。
3. 讲故事时的正确姿势:**验收口径按 oracle 报告并明确标注**;claim 差距作为"发现的部署级开放问题 + 系统性实验证据"呈现(这本身是高质量的技术发现:注册条件化增强的冒认泄漏机理 + 12 臂 trade-off 前沿)。
4. v8d_sil 的 1s/5s 官方轴(9.3 凌晨跑完,`claim_fix/final_v8d_gpu0_main.log`):oracle 口径 ERes2Net 1s 13.12/14.36、5s 4.27/4.80;ECAPA 1s 17.66/18.92、5s 5.48/6.18;B6 1s 17.98/20.45、5s 7.09/8.78。

## 6. 方法原理

### 6.1 TSE 前端(核心创新,9.20M 参数)
**骨架:** FullSubNet+(全-子带降噪网络:全带模型 512 隐藏 LSTM 建模全局噪声上下文,子带模型 384 隐藏建模频带细节;257 维频域,STFT 512/256)。
**条件化(创新点):** SpeakerFiLM 模块(约 528K 参数)——注册语音过冻结声纹后端得 512 维嵌入 → FiLM(Feature-wise Linear Modulation)仿射调制全带模型三路输入,**"末层零初始化=恒等起步"**(保证训练起点等价于原版前端,不破坏已有能力)。
**推理:** 逐 utt 用该句注册语音(clean enrollment)提嵌入 → 条件化增强 → 增强语音再提声纹嵌入 → 余弦打分。

### 6.2 损失族(训练日志可见的分量)
- **L_se**:cIRM 信号重建 MSE(防退化锚,保证增强语音不劣化)
- **L_ce**:AAM-CE 判别损失(增强语音嵌入过冻结验证器 soup5,梯度穿回前端——VoiceID Loss 思路)
- **L_spk**:说话人保持损失 1−cos(e_enh, e_clean)(Phase 1 加)
- **L_ns**:非目标抑制,top-K 原型难负 hinge(τ=0.30, TOPK=8,Phase 2 加)
- v6/v8 补救臂再加:imp(冒认条件暴露)、mix、rank、sil(冒认静音掩蔽)、hardcos 等
- 随机时长增强:{1,2,3}s 段级随机(修 1s 短语音)

### 6.3 训练纪律(值得在报告里讲的工程方法)
- **proxy validation 选点 + 官方冻结单次**:融合权重/选点只在 100 个未见说话人的 proxy 集上搜(`8.27/build_proxy_val.py`,trial 1:5.5 对齐官方),官方测试每个决策只跑一次,杜绝测试集过拟合
- **种子固定 2026、训练/测试噪声池隔离(615 训练 vs 168 held-out)、说话人隔离**
- 启动守卫:前端 ckpt 与 config 一致性校验、manifest 完整性校验(8.22)
- 收敛守望器:增益 <0.08 自动停(8.28)

### 6.4 后端侧(并行线)
- ERes2Net 五条件匹配域鲁棒微调(90k 数据):单独杠杆 -8%~-11%
- **soup5**:五模型权重平均(ERes2Net,实测 29.06M 含头),raw 0dB 7.61/-5dB 9.71
- ECAPA 镜像微调(20.81M)、B6 适配(8.28-8.29 fix_b6/fix_raw_b6)

## 9. 局限性(诚实清单)

1. **claim 口径未解决**(最大局限):部署真实口径下前端为负增益,12 臂未破解;需未来工作(如冒认感知训练、分数域校正、注册条件 dropout)
2. **speech 人声域盲区**:非人声域 -40%+,竞争说话人域几乎无增益(-13.5%/+0.8%)——注册条件化理论上是多人场景解药,但 overlap 分项(r5)仅 -25.8%/-35.2%,且 overlap2_en 只有 -15%
3. **1s 短语音**:0dB 档 -26.9%,差 3pp 未过线
4. **ReDimNet2-B6 跨框架迁移打折**:-23.7%/-28.2%,差约 2pp
5. oracle 口径依赖真实说话人条件化,部分场景"增强优于 clean"的机理(通道归一+注册信息注入)需部署口径佐证——而 claim 重测显示该优势在冒认场景不可用
6. 挑战目标(EER≤0.5%)未冲击,与目标差距数量级
7. 共享 GPU 受限导致迭代周期长(工程性,非方法性)

## 10. 一句话叙事线(答辩/汇报用)

> "我们从三模型全量基线出发建立可信评测体系;首版微调和通用降噪两条自然路线先后被证伪(6/8 条件变差、降噪反而抹掉身份特征);由此发现单说话人噪声的本质是'干扰语音'问题,发明了注册声纹 FiLM 条件化的目标说话人提取前端(9.2M 参数),配合说话人保持与非目标抑制两级损失和随机时长增强,四轮迭代把两个主后端的 0dB/-5dB EER 相对降幅做到 **-41.7%~-50.4%**,超额完成 -30% 验收线,并在时长、噪声域、混响、重叠全轴验证;进一步按部署真实口径(claim-conditioned)主动复测,发现并系统刻画了注册条件化增强的'冒认泄漏'机理与 12 臂 oracle-claim trade-off 前沿——这是本课题留下的最重要开放问题。"
