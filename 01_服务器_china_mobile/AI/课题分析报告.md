# 子课题一 vs 子课题二 —— 区别、要求与硬性条件分析

> 基于 `任务.xlsx` 完整内容整理，2026-07-19

## 一、总览：两个子课题的核心区别

| 维度 | 子课题一 | 子课题二 |
|------|----------|----------|
| **核心问题** | **噪声鲁棒性**：模型在恶劣声学环境下还能不能认准人？ | **时间稳定性**：同一个人的声音随时间变化后，模型还能不能认准？ |
| **变量** | SNR、回声、混响、多人重叠、短语音、跨设备 | 时间跨度（0→8周）、设备/环境变化、健康/疲劳/情绪 |
| **关注点** | 声学条件 → 识别精度 | 时间漂移 → 模板老化 |
| **主要方法** | 数据增强、鲁棒训练、去混响、目标说话人提取、域适配 | 多时段注册、质量加权模板、高置信度自适应更新 |
| **评测核心** | 不同 SNR 下的 EER、minDCF | 不同时间点 (T0-T3) 的 EER 降幅、模板安全更新率 |

**一句话总结：**
- **子课题一**要解决的是"**听不清**"的问题（环境噪声干扰）；
- **子课题二**要解决的是"**人变了**"的问题（声纹随时间漂移）。

## 二、子课题一：多条件中文声纹识别与噪声鲁棒性增强

### 2.1 任务目标

面向 AI 眼镜、车载座舱等智能终端，构建**开集声纹验证模型**，使其在低信噪比、回声、混响、多人重叠、短语音和跨设备等复杂条件下保持稳定识别能力。

### 2.2 数据要求

| 项目 | 规定 |
|------|------|
| 主训练数据 | **3D-Speaker 中文数据集** |
| 辅助数据 | VoxCeleb **仅用于预训练、迁移或公开基线** |
| 数据划分 | 训练/验证/测试按**说话人互不重叠**划分，禁止同一说话人或同源语音切片跨集合泄漏 |
| 任务类型 | **开集声纹验证**（非闭集分类），测试阶段目标说话人不出现在训练集 |
| 注册/测试 | 固定注册语音数量/时长，测试语音时长分 **1s、3s、5s** 三档，正负试验清单与比例固定 |
| 阈值规则 | 阈值**仅在验证集**确定，测试集上**冻结**，不得重新调参 |

### 2.3 测试场景（全部必须覆盖）

| 场景 | 说明 |
|------|------|
| 干净语音 | 无干扰基线 |
| 单说话人噪声 | SNR = **-5 dB** 和 **0 dB**（核心挑战场景） |
| 回声/混响 | 记录 RIR / T60 |
| 2-3 人重叠 | 记录目标与干扰说话人的能量比 TIR（干扰可为中文/英文） |
| 跨设备 | 不同录音/播放设备 |
| 短语音 | 极短时长测试 |

### 2.4 基线设置

- 主验收基线：原始 **ReDimNet2 / ERes2Net-large** 等，使用相同 3D-Speaker 中文数据划分，**不使用任何前端增强、噪声鲁棒训练、域适配或后端校准**
- 若采用其他骨干网络，还需与该骨干的**未增强版本**进行同条件比较

### 2.5 允许的技术路线

数据增强、鲁棒训练、去混响、波束形成、目标说话人提取、域适配、多任务学习、后端校准、联合训练等，**不限于前端增强**。

### 2.6 核心指标要求

#### 挑战目标（仅针对"单说话人噪声"场景，不含回声/混响/重叠）

| SNR 档位 | 挑战目标 |
|----------|----------|
| -5 dB | EER ≤ **0.5%** |
| 0 dB | EER ≤ **0.5%** |

#### 未达挑战目标时的保底要求

| SNR 档位 | 保底要求（相对基线） |
|----------|----------------------|
| -5 dB | 相对 EER 降幅 ≥ **30%** |
| 0 dB | 相对 EER 降幅 ≥ **30%** |

> 计算公式：（对应档位基线 EER - 改进模型 EER）÷ 对应档位基线 EER × 100%

#### 其他场景

不设统一硬阈值，**分项报告** EER、minDCF、ROC/DET 和固定阈值 FAR/FRR，**禁止以合并均值替代分项结果**。

### 2.7 交付物

1. 中文多条件鲁棒声纹识别**模型权重**
2. **训练/评测代码**
3. **对比分析报告**（含 EER、minDCF、FAR/FRR、ROC/DET 及失败案例）

## 三、子课题二：跨时间周期声纹建模与长期稳定性

### 3.1 任务目标

研究同一说话人在**天至 8 周尺度**上的声纹漂移规律，形成可延伸至**半年以上长期验证**的模板更新方法和评测协议。

### 3.2 时间点设计

| 时间点 | 定义 | 用途 |
|--------|------|------|
| **T0** | 第 1 周采集 | **注册语音**，建立静态模板（主验收基线） |
| **T1** | 第 3-7 天 | 短期漂移 |
| **T2** | 第 2-4 周 | 中期漂移（完成/挑战指标节点） |
| **T3** | 第 6-8 周 | 长期漂移（完成/挑战指标节点） |

- 目标说话人**不出现在模型训练集**
- 验证集设置工作点阈值为 **FAR = 0.1%**，测试阶段冻结，同时报告 EER 和 minDCF

### 3.3 数据要求

| 项目 | 规定 |
|------|------|
| 第一步 | 先核验 3D-Speaker 的同一说话人多会话数据 |
| 第二步 | 补充 **8 周纵向中文采集**，固定文本/自由说话条件、语音时长和采集质量 |
| 半年以上数据 | 若有历史数据可做长期补充验证，**不作为必达验收项** |

**人员规模要求：**

| 指标档位 | 人数 | 时点数 | 有效跨度 |
|----------|------|--------|----------|
| 完成指标 | ≥ **30 人** | ≥ **4 个**（T0/T1/T2/T3） | ≥ **6 周** |
| 挑战指标 | ≥ **50 人** | ≥ **5 个** | ≥ **8 周** |

### 3.4 实验设计

| 实验 | 作用 |
|------|------|
| **同设备 + 同环境** | 主实验，分离纯时间漂移 |
| **跨设备 / 跨环境** | 单独对照，防止通道变化被误判为时间漂移 |
| **状态记录** | 记录健康、疲劳、情绪等，避免状态变化混淆分析 |

### 3.5 基线设置

- 主验收基线：原始 ReDimNet2 / ERes2Net-large 等 + **T0 单时点静态模板且不更新**
- 采用其他骨干时，还需与该骨干的 T0 静态模板版本同条件比较

### 3.6 允许的技术路线

- **重点方法**：多时段注册、质量加权模板、高置信度自适应更新
- **扩展项**（加分但不强制）：持续学习、时间不变表征

### 3.7 核心指标要求

#### 完成指标（必达）

| 指标 | 要求 |
|------|------|
| T2/T3 EER 相对下降 | ≥ **10%**（相对 T0 静态模板基线） |
| T2/T3 minDCF 相对下降 | ≥ **5%** |
| 验证集 FAR=0.1% 冻结阈值 → 测试集 | FAR ≤ **0.2%** |

#### 挑战指标（冲刺）

| 指标 | 要求 |
|------|------|
| T2/T3 EER 相对下降 | ≥ **20%** |
| T2/T3 minDCF 相对下降 | ≥ **10%** |
| 冻结阈值下测试集 FAR | ≤ **0.1%** |
| 冻结阈值下测试集 FRR | 相对主验收基线下降 ≥ **15%** |

#### 安全指标

| 指标 | 完成档 | 挑战档 |
|------|--------|--------|
| 误更新率 | ≤ **0.5%** | ≤ **0.1%** |
| 历史时点 EER 相对上升 | ≤ **10%** | ≤ **5%** |

> 误更新率 = 错误样本更新次数 ÷ 全部更新次数 × 100%

### 3.8 交付物

1. **0 至 8 周指标曲线**
2. **同/跨设备对照结果**
3. **模板更新方案**
4. **消融与失败案例分析**
5. **代码和评测脚本**

## 四、两个子课题的关键区别总结

| 对比维度 | 子课题一 | 子课题二 |
|----------|----------|----------|
| **核心挑战** | 声学环境恶劣 → 信号被破坏 | 时间流逝 → 声纹特征漂移 |
| **自变量** | SNR、混响、重叠、设备 | 时间跨度（T0→T3）、健康/情绪状态 |
| **评测逻辑** | **横比**：同一时间段不同声学条件下比基线 | **纵比**：同一人不同时间点比 T0 静态模板 |
| **基线** | 未增强的干净模型 | T0 静态模板 + 永不更新 |
| **关键指标** | 各 SNR 下的 EER 绝对值 ≤ 0.5% | 各时点的 EER **相对降幅** ≥ 10%/20% |
| **独特指标** | 无 | **安全指标**（误更新率、历史时点退化） |
| **技术重点** | 前端增强、鲁棒训练、去混响 | 模板更新策略、质量加权、自适应 |
| **数据需求** | 大规模带噪中文数据 | **纵向追踪数据**（同一批人反复录 8 周） |
| **人员参与** | 不需要固定人员长期配合 | **必须**同一批人 8 周内反复录音 |

## 五、完成两个课题至少需要的硬性条件

### 5.1 GPU 算力

| 条件 | 说明 |
|------|------|
| GPU | 至少 **1 块 24GB+ 显存**的 GPU（如 RTX 4090 / A5000 / A100），推荐 **多卡** |
| 理由 | 需要训练/微调 WavLM、ReDimNet2、ERes2Net-large 等大参数量声纹模型；子课题一还需要大量数据增强和多次消融实验 |

### 5.2 数据集

| 条件 | 说明 |
|------|------|
| **3D-Speaker 中文数据集** | 两个子课题的**核心数据源**，必须获取完整访问权限 |
| VoxCeleb（可选） | 子课题一允许用于预训练/迁移，非必需 |

### 5.3 录音设备与环境（两个子课题都需要）

| 条件 | 说明 |
|------|------|
| 高品质麦克风 | 至少 1 套专业录音设备（如 Audio-Technica、Shure 等品牌电容麦 + 声卡） |

### 5.5 软件与开发环境

## 六、两个课题的内在关系

两个子课题解决的是**声纹识别在不同维度上的鲁棒性**：

- **子课题一**：空间/设备维度的鲁棒性——不管在什么环境、用什么设备，都能认准人
- **子课题二**：时间维度的鲁棒性——不管过了多久，都能认准人

两者**可以共享**：
- 基础声纹模型架构（ReDimNet2 / ERes2Net-large 等）
- 3D-Speaker 数据预处理管线
- 评测框架（EER、minDCF、ROC/DET 计算逻辑）
- GPU 和录音硬件

两者**独立且互不替代**：
- 子课题一**不要求**同一个人多次录音，可以用大规模多说话人数据
- 子课题二**不要求**噪声/混响等复杂声学条件，主实验在同设备同环境下进行
- 评测逻辑完全不同：一是 SNR 横比，一是时间纵比

> **建议**：如果资源有限，可以共享基础模型和 GPU，但**人员和时间是子课题二独有的硬约束**，必须提前启动人员招募和数据采集计划。

## 七、难度对比：子课题一 vs 子课题二，哪个更难？

### 7.1 分维度对比

| 维度 | 子课题一（噪声鲁棒性） | 子课题二（时间稳定性） | 更难的 |
|------|----------------------|----------------------|--------|
| **技术深度** | 需要掌握数据增强、鲁棒训练、去混响、波束形成、域适配等多种技术栈 | 核心方法是模板更新/质量加权，技术栈相对收敛 | ✅ 子课题一 |
| **实验复杂度** | 6+ 种声学场景 × 多种 SNR × 多模型对比，实验矩阵巨大 | 4-5 个时间点 × 设备/环境对照，实验规模可控 | ✅ 子课题一 |
| **GPU 算力** | 需要训练大模型 + 多轮消融实验，算力需求高 | 推理和模板更新为主，训练量相对小 | ✅ 子课题一 |
| **数据获取** | 3D-Speaker + 公开噪声/RIR 数据即可开始，**零等待** | 需要 30-50 人 8 周持续配合，**无法加速** | ✅ 子课题二 |
| **不可压缩的硬约束** | 无，多卡并行可加速 | 数据采集必须跨 8 周，T3 最早第 6 周才能拿到 | ✅ 子课题二 |
| **失败风险** | 模型训不好可以调，数据始终在那 | 如果参与者中途退出、录音质量不达标，**整个课题崩塌** | ✅ 子课题二 |
| **评测指标独特性** | EER/minDCF 等标准声纹指标 | 标准指标 + **独有的安全指标**（误更新率 ≤0.5%、历史时点退化 ≤10%），评测更复杂 | ✅ 子课题二 |
| **可复现性** | 公开数据 + 代码 → 完全可复现 | 自采数据难以复现，评审时可能受到更多质疑 | ✅ 子课题二 |

### 7.2 总评

```
子课题一：技术更难，但可控。
子课题二：管理更难，且不可控。
```

- **子课题一像"刷榜"**：数据在那、基线在那、指标在那，拼的是工程能力和实验设计，可以用 GPU 数量换时间。
- **子课题二像"田野调查"**：核心瓶颈不是代码而是**人**——招募、排期、催录音、质量检查、人员流失应对。技术上模板更新/质量加权并不比鲁棒训练复杂，但数据的不可替代性让它更脆弱。

**我的判断：子课题二更难。** 不是难在算法，而是难在不完全由你掌控。代码写错了可以改，GPU 不够可以租，但 30 个人连续 8 周按时录音——这件事技术能力几乎帮不上忙。

> 如果你只有一个人 + 8 周时间，**子课题二是你的关键路径**。必须第 1 天启动数据采集，否则第 8 周拿不到 T3 数据。

### 8.2 周级详细计划

#### **第 1 周：环境搭建 + 基线复现 + 数据采集启动**

| 课题 | 任务 | 产出 |
|------|------|------|

### 9.3 子课题二：必须自己采集数据吗？

**直白回答：是的，必须自己采集。**

理由有四个层级：

1. **任务文档明确要求**："再补充 8 周纵向中文采集"——这是写在正式要求里的，不是可选的。

2. **验收指标绑定**："完成指标不少于 30 人、每人不少于 T0/T1/T2/T3 四个时点、有效跨度不少于 6 周"——目前没有任何公开数据集同时满足：中文 + ≥30 人 + ≥4 个精确时间点 + ≥6 周跨度 + 同设备同环境。

3. **实验设计要求**："设置同设备、同环境的主实验……避免把状态或通道变化误判为纯时间漂移"——公开数据集的 session 间隔和设备/环境不受控，根本分不清 EER 退化是因为时间还是因为换了麦克风。

4. **安全指标的特殊性**：误更新率（≤0.5%/0.1%）和历史时点退化（≤10%/5%）这两个指标在其他声纹数据集中几乎没见过，需要专门设计试验协议。

#### 但你可以这样降低采集成本

```
┌─────────────────────────────────────────────────────────┐
│  策略：公开数据做方法开发 + 自采数据做最终验收            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  第 1-5 周（方法开发阶段）：                              │
│    • 用 3D-Speaker 多会话数据模拟 T0-T3 协议             │
│    • 用 CN-Celeb 做跨设备/跨时间的补充实验                │
│    • 开发和调试模板更新算法                               │
│    → 这个阶段不需要等自采数据                             │
│                                                         │
│  第 1-8 周（数据采集并行进行）：                          │
│    • 第 1 周：录 T0（≥30 人）                            │
│    • 第 1-2 周：录 T1                                    │
│    • 第 2-5 周：录 T2                                    │
│    • 第 6-8 周：录 T3                                    │
│    → 采集和开发完全解耦，互不阻塞                         │
│                                                         │
│  第 6-8 周（最终验收）：                                  │
│    • 在自采数据上跑通关评测                                │
│    → 这时方法已经成熟，只需换数据跑一遍                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

| 参数 | 建议值 | 理由 |

| 文本 | 准备 10 句固定中文短句 | 固定文本条件 |
| 周期 | T0: D1-2, T1: D5-7, T2: D14-21, T3: D42-49 | 覆盖要求跨度 |
