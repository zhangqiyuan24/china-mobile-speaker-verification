# 面试项目介绍讲稿(3 分钟版)· 张启元

> 项目:多条件中文声纹识别与噪声鲁棒性增强(中国移动"梧桐·鸿鹄"暑期线上实习 · 子课题一)
> 用法:正文约 900 字,正常语速 3 分钟。所有数字均为官方测试集实测,与报告/PPT 一致,可放心被追问。
> 红线提醒:不要说"抑制跨设备信道偏差"(属过度声明,我们是复合条件实测);不要提"失败样本加权重采样"(项目里不存在重采样)。

## 一、正文讲稿

### 【开场:背景与任务】(约 20 秒)

我在中国移动"梧桐·鸿鹄"暑期实习做的是子课题"多条件中文声纹识别与噪声鲁棒性增强"。场景是 AI 眼镜、车载座舱这类终端上的**开集声纹验证**:用户念几句注册语音建立声纹模板,之后系统判断一句话"是不是这个人"。难点是真实环境的噪声,验收指标很硬:在 0 dB 和 -5 dB 两档低信噪比下,等错误率 EER 相对基线模型要**降低 30% 以上**,而且只能在验证集定阈值、测试集冻结,不许调参。

### 【难点:两条自然路线都被证伪】(约 40 秒)

这个任务最自然的两条路,我们一开始都试了,都被数据证伪。第一条是**微调声纹模型本身**——冻结底层、分层学习率,结果八个测试条件里六个变差。第二条是**前面串一个通用降噪网络**再验证,结果降噪后错误率反而比不降噪还高 1.7 个百分点。我们没有放过这个负结果,深挖下去发现:降噪把跨句稳定的**说话人身份特征抹平了**,目标对的打分均值从 0.422 掉到 0.391。再往上想一层:这个任务里的"噪声"常常是**另一个说话人在说话**,而通用降噪器的目标是"保留所有语音、去掉非语音",所以它天然会保留干扰人声——不是降噪器做得不好,是**任务定义错了**。

### 【方法:注册条件化目标说话人提取】(约 60 秒)

由此我们把问题重新定义为**目标说话人提取**:注册语音本来就是验证系统自带的输入,那就用它告诉前端"该提取谁"——只保留注册说话人,压制其他一切声音。实现上,注册语音的声纹嵌入经一个仅 0.52M 参数的 **FiLM 模块**,对 FullSubNet+ 降噪网络的特征做逐通道仿射调制;FiLM 末层零初始化,训练起点严格等于原模型,不破坏基座能力。声纹后端全程**冻结**,只训前端 9.2M 参数,训练和推理用同一个验证器,目标完全一致。损失函数四项配合:信号重建损失做锚,防止前端退化成"乱提取";说话人保持损失把增强语音的嵌入拉回注册方向;**难负原型抑制损失**——在一个九千九百类的冻结原型库里,每个 batch 在线挑出与注册者最容易混淆的 8 个难负原型,用间隔 0.3 的合页惩罚把嵌入推开,直接拉大判别间隔——这里强调一句,难例利用完全发生在损失函数内部,**数据侧没有任何重采样**;再加一个角间隔分类损失,分类头由冻结原型初始化,相当于一个"免费教师"。之后同配方延长续训、随机时长增强,逐级验证。

### 【结果】(约 25 秒)

最终官方测试集 138 万条 trial 上,主力后端 0 dB / -5 dB 的 EER 从 8.39 / 11.06 降到 **4.89 / 5.56**,相对降幅 **41.7% 和 49.7%**,大幅超过 30% 验收线;换经典后端 ECAPA 也拿到 43%-50% 的降幅,说明增益来自前端本身、可跨后端迁移。clean 语音不但不退化还略有提升,纯音乐、音效这些非人声噪声域的增益也全额迁移。

### 【边界与收获】(约 25 秒)

我们也主动按部署真实口径做了加压检验,发现了"注册条件信息会泄漏进增强语音"这样的开放问题,并系统刻画了十五组补救方案的权衡前沿——这块我认为是整个实习里最有科研含金量的发现。这个项目给我最大的训练是:**用严格的评测纪律把想当然的路线逐条证伪,再让负结果的机理指向正确的问题定义**,而不是上来就堆方法。

## 二、30 秒电梯版(备用)

我做的是终端场景的声纹验证降噪鲁棒性。基线模型在 0/-5 dB 噪声下错误率飙升,直接串通用降噪反而更差——因为噪声常常是另一个说话人,而通用降噪会保留所有语音。我把问题重定义为目标说话人提取:用注册语音的嵌入通过 FiLM 调制降噪网络,只提取注册人;配合说话人保持、难负原型抑制等四个损失。官方 138 万条测试上,EER 相对降幅 41.7%/49.7%,远超 30% 验收线,且可跨后端迁移、clean 不退化。

## 三、常见追问与答法要点

| 追问 | 回答要点 |
|---|---|
| 为什么微调声纹模型不行? | 试过:冻结卷积底层+分层学习率,clean 占比 15%,官方八条件六个变差。开集测试说话人不在训练集,带噪微调会把模型拉向噪声分布、丢失判别面。 |
| 通用降噪为什么负增益?数字? | 0 dB 下降噪后 EER 10.11 vs 带噪直测 8.39,差 1.72pp;机理:目标对余弦均值 0.422→0.391,身份特征被抹平;根因:降噪先验"保留所有语音"与任务冲突。 |
| FiLM 是什么?为什么不拼接条件向量? | Feature-wise Linear Modulation:条件经 MLP 生成逐通道 γ、β 仿射调制特征,让条件参与每一层的特征组合;拼接只影响输入层。末层零初始化(γ=1,β=0)保证起点恒等,是增量训练的工程保险。 |
| 后端为什么不一起训? | 一起训会破坏后端在 clean 上的判别力,且部署要重验证后端;冻结后端 + 梯度只回前端,训练与推理同验证器,目标严格一致;分类头用冻结原型当"免费教师"。 |
| 难负原型抑制是不是难例挖掘+重采样? | 不是。原型库是冻结分类头的 9,900 个类中心(静态地图);每个 batch 在线算余弦、排除真说话人、取 Top-8 最难原型施加 hinge(τ=0.3)。数据侧零改动、无重采样加权——"难例利用"只在损失内部和验证选点两处。 |
| 结果怎么保证可信、没有偷看测试集? | 四道纪律:说话人/噪声池/MD5 三重隔离防泄漏;阈值只在验证集定、测试集冻结;所有选点在 100 个未见说话人的代理验证集(含困难试验子集)上做;官方测试每个决策只跑一次。复算脚本与官方打分逐位对齐。 |
| 部署时有人冒认别人的身份怎么办? | 这是我们主动加压检验的口径(claim):冒认者用受害者的注册语音做条件,会把冒认语音"往受害者拉",冒认分数中位数抬升约 3 倍。15 组训练侧+推理侧补救画出了权衡前沿,最优臂 claim 已优于 raw 但 oracle 退到线外——结构性机理,构成开放问题。验收条款给定的口径(测试句绑定真实说话人)不受影响。这个答案体现深度,建议主动、坦然地讲。 |
| 加了前端之后推理慢多少?划算吗? | 实测过(P100 批量,同批 16,401 句×3s):原始路径仅后端嵌入 31.9 ms/句;前端增强 40.0-40.7 ms/句(两次独立实测一致 ±2%);整链约 72 ms/句,RTF ≈ 0.024,单句耗时约 2.3 倍——前端参数只有后端 1/3,但全带+257 子带 LSTM 逐帧展开计算密度高,所以开销约为后端的 1.3 倍。RTF 远小于 1,实时无虞;终端 NPU 上量化后还有压缩空间。 |
| 最大的困难/踩的坑? | 早期代理验证集负对过易、系统性乐观 5pp+,全部换困难口径;困难集预测幅度高估约 5 倍,立了"移动<1pp 不动官方"的铁律;延长续训第 4 段回归 +17.7% 按预声明止损停机。 |
| 如果再做两个月? | ①claim 泄漏修复:条件 dropout/扰动训练、分数域校准、只在掩码估计端注入条件+输出端身份中和;②人声干扰盲区:重叠语音训练+分离前端级联、目标嵌入+干扰负原型双条件;③轻量后端(12.7M)增益打折,用其自身当验证器重训前端做判别面匹配。 |
| 为什么不用大模型(WavLM 之类)? | 试过:WavLM-base 零样本 EER 35%+,中文 90k 数据微调后 20.9%,仍大幅落后 29M 监督模型(8.39)——中文域匹配与数据规模比参数量更关键。这也支撑了"中等骨干+轻量前端"的性价比结论。 |
| 团队怎么分工? | 我负责算法与实验主线(路线设计、训练管线、全部官方评测、报告);同伴负责评测协议与数据(多条件测试数据合成、泄漏检查、统一评测脚本、文献调研)。 |
